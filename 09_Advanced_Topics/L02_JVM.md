## ⭐ JVM 是什么？

> JVM = **Java Virtual Machine（Java 虚拟机）**
> 它让 Java 代码能在任何操作系统上运行（"一次编写，到处运行"）

```
Java 源码 (.java)
    ↓ javac 编译
字节码 (.class)
    ↓ JVM 加载执行
机器码（各操作系统不同）
```

## ⭐ JVM 内存结构

```
┌─────────────────────────────────────┐
│              JVM 内存                │
│                                     │
│  ┌──────────────────────────────┐  │
│  │      堆（Heap）— 最大区域      │  │  ← 对象实例在这里（new 出来的东西）
│  │  ┌────────┐  ┌────────────┐  │  │
│  │  │  新生代  │  │    老年代    │  │  │
│  │  └────────┘  └────────────┘  │  │
│  └──────────────────────────────┘  │
│                                     │
│  ┌──────────┐  ┌──────────────┐    │
│  │   栈     │  │   方法区       │    │  ← 栈：局部变量、方法调用
│  └──────────┘  └──────────────┘    │  ← 方法区：类信息、常量
└─────────────────────────────────────┘
```

### 核心概念
| 区域 | 存什么 | 说明 |
|---|---|---|
| **堆（Heap）** | new 出来的对象 | 最大、GC 主要管理的区域 |
| **栈（Stack）** | 局部变量、方法调用 | 每个线程一个栈 |
| **方法区** | 类信息、常量、静态变量 | 所有线程共享 |

## ⭐ 垃圾回收（GC）

> GC = **自动回收不再使用的对象**，释放内存

```java
User user = new User();  // 在堆上创建对象
user = null;              // 没有引用指向它了 → GC 会回收它
```

### GC 过程（简化版）
```
新对象 → 新生代（Eden 区）
    ↓ 经过几次 GC 还活着
         → 老年代
              ↓ 老年代满了
                   → Full GC（耗时较长，尽量避免！）
```

### 常用 GC 收集器
| 收集器 | 特点 | 适用 |
|---|---|---|
| G1 GC | 默认，均衡 | 大部分项目 ✅ |
| ZGC | 低延迟 | 大内存、低延迟要求 |

## ⭐ 常用 JVM 参数

```bash
# 设置堆内存大小
java -Xms512m -Xmx1024m -jar app.jar
# -Xms：初始堆大小
# -Xmx：最大堆大小

# 生产环境推荐设置相同（避免动态扩容）
java -Xms1g -Xmx1g -jar app.jar

# 打印 GC 日志（排查问题时用）
java -Xlog:gc* -jar app.jar
```

## 💡 常见内存问题

| 问题 | 原因 | 解决 |
|---|---|---|
| `OutOfMemoryError: Java heap space` | 堆内存不够 | 增大 -Xmx 或排查内存泄漏 |
| `StackOverflowError` | 递归太深 | 检查递归出口条件 |
| 频繁 Full GC | 老年代对象太多 | 排查对象生命周期 |

> 💡 遇到内存问题，先用 `jmap` 和 `jstack` 命令排查，或用 VisualVM 工具
